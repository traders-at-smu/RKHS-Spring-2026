KEY FINDINGS:

Phase 1 — Single-Stage KRR (Runs 1-6):
  - Bar-level evaluation was misleading (Runs 1-3 looked profitable, Run 4 revealed daily loss)
  - Increasing regularization made things worse (Run 5)
  - VannaCharm/GammaExposure proxy features added noise (Run 6) — need real Greeks

Phase 2 — Two-Stage ElasticNet (Runs 7-9):
  - Decoupling kernel predictions from signal combination was the breakthrough (Run 7)
  - Longer prediction horizons (5d, 10d) didn't help — kernels can't predict multi-day returns (Runs 8-9)

Phase 3 — Kalman Filter (Runs 10-13):
  - Auto-tuned Q was too conservative (Run 10)
  - Aggressive Q was the performance unlock (Run 11)
  - [WITHDRAWN] "Null test confirmed kernels drive the entire edge: Sharpe 1.55 with vs
    -1.01 without (Run 12 vs 13)". Re-measured on the fixed pipeline with
    validate_pipeline.py across seeds 0/1/2: real features 0.28 +/- 1.18, features
    replaced by pure noise 1.18 +/- 1.25, target shuffled 1.15 +/- 1.08. The kernels
    are not distinguishable from noise, and a target that cannot be predicted by
    construction scores better than the real one. See POSTMORTEM.md.
  - Lower thresholds + transaction costs = best overall config (Run 13)

Phase 4 — Hyperparameter Tuning (Runs 14-15):
  - Per-kernel tuning revealed: fast kernels need ℓ=5.0, slow need ℓ=0.1 (was 1.0 for all)
  - Kyle/Hawkes want ν=2.5 (smooth), Macro wants ν=0.5 (rough)
  - Macro got first non-zero ElasticNet weight (-0.024) — but negative, causing drawdown (Run 14)
  - Clamping to positive weights zeroed everything again but gave 63.6% hit rate on 8 trades (Run 15)
  - Run 13 remains best overall configuration

Phase 5 — Robust Loss + Adaptive Q (Runs 16-17):
  - Huber loss correctly identifies zero predictive signal → zeros all weights → Sharpe -0.44 (Run 16)
    Key insight: MSE-based ElasticNet is slightly "fooled" by outliers into keeping small weights
    that the Kalman can use. Huber is "too honest" — confirms kernels don't predict returns.
  - Adaptive Q (2-regime: high conviction vs low conviction) + tuned kernels → Sharpe 1.27 (Run 17)
    Better than Run 14 on W/L ratio (1.39x vs 1.36x), but lower Sharpe than Run 13 (1.27 vs 1.55)
    Adaptive Q underperforms fixed aggressive Q because only 1 kernel (Macro) has non-zero weight —
    kernel agreement dispersion is meaningless with 5/6 kernels contributing zero signal.
  - Both improvements need more kernel diversity (Sentiment + Greeks) to be effective.

Phase 6 — Real Greeks Integration (Runs 18-19):
  - Anders delivered vanna_charm_bars.parquet: 2,327 intraday bars of net_vanna + net_charm
  - Run 18: Wired real Greeks into VannaCharm kernel (6D features: levels + rate-of-change +
    directional hedging pressure + decay/hedging ratio). OOS correlation flipped from -0.016
    (proxy) to +0.010 (real) — positive signal, but still too weak for ElasticNet.
  - Adding VannaCharm as 7th kernel shifted ElasticNet regularization → ALL weights zeroed
    (including Macro which previously had -0.024). Result: Sharpe 1.04, 2 trades.
  - Run 19 (fixed weights, bypassing ElasticNet) revealed:
    • VannaCharm alone (+0.02): Sharpe 0.06, 200 trades, 48.9% hit rate — roughly flat
    • Macro alone (-0.024): Sharpe -1.46, 32 trades — DESTRUCTIVE with fixed weight
    • Both together: Sharpe -1.49
    • All-zero weights + Kalman: Sharpe 1.04 — OUTPERFORMS all fixed-weight configs
  - Key insight: Profitability comes from the Kalman filter's interaction with the ElasticNet's
    time-varying intercept/structure, NOT from any static kernel weight. Fixed weights don't
    capture the walk-forward dynamics that the ElasticNet provides.
  - Architectural finding: 4 microstructure kernels (LOB, VPIN, Kyle, Hawkes) all read the
    same order flow tape → redundant in prediction space. v2 should consolidate into 1
    "OrderFlow" kernel + Sentiment + Greeks + Macro (4 independent info sources).
    VPIN/Hawkes demoted to position-sizing gates rather than prediction kernels.

Phase 7 — v2 Architecture + Sentiment (Runs 20-21):
  - Run 20: Wired Sentiment kernel (GDELT/FinBERT 128D→PCA 10D + n_headlines). OOS correlation
    +0.023 — strongest positive signal of any kernel. Confirmed PCA eliminates noise.
  - Run 21: v2 architecture deployed:
    • OrderFlow kernel: LOB+VPIN+Kyle+Hawkes consolidated via expanding-window PCA (61D→15D).
      PCA captures 97.0% of variance — confirms 4 kernels were measuring same signal.
    • Fast = [OrderFlow (15D), VannaCharm (6D)]; Slow = [VRP (10D), Macro (6D), Sentiment (11D)]
    • VPIN/Hawkes demoted to position-sizing gates (scale position 0.5–1.0 based on toxicity/burst)
    • Result: Sharpe 1.38, Sortino 2.43, Max DD 6.9%, 20 trades, 54.7% hit rate
    • Max DD improved from 7.7% (Run 13) to 6.9% — position-sizing gates are working
    • All ElasticNet weights still zero — same Kalman intercept mechanism drives profitability
    • Fewer kernels (5 vs 6-7) → more stable ElasticNet regularization path
  - Comparison to Run 13 (v1 best): Sharpe 1.38 vs 1.50 (-8%), but better drawdown profile
    and architecturally cleaner (4 independent info sources, no redundant CKA checks)

Phase 8 — Vol Target + Hybrid (Runs 22-25):
  - Run 22: Pure Ridge (l1=0) forced non-zero kernel weights. All 5 kernels got weights, but
    performance worse (Sharpe 1.26 vs 1.38). Confirms ElasticNet zeroing is correct — small
    weights add noise that the Kalman can't overcome.
  - Runs 23-24: Retargeted kernels to predict forward realized vol instead of returns.
    RKHS is traditionally used for classification/regime detection, not return prediction.
    Results confirmed kernels predict vol 9x better than direction (combined corr +0.122 for
    vol vs +0.007 for returns). Per-kernel vol correlations: VRP +0.067, Sentiment -0.085,
    Macro -0.038. But translation to profitable positions is hard — momentum direction gave
    Sharpe -0.05, dvol direction gave 0.80 with only 12 trades.
  - Run 25★ (HYBRID): Combined the best of both approaches:
    • Return-prediction Kalman for entry/exit timing (more trades, better timing)
    • Trailing realized vol for inverse-vol position sizing (scales down in high vol)
    • Vol-targeting: 15% annualized vol target, mean scale 0.62 (average position 62% of max)
    • Result: Sharpe 1.56, Sortino 2.85, Max DD 3.6%, W/L 1.77x
    • Max DD improved from 6.9% (Run 21) to 3.6% — vol sizing cuts drawdown nearly in half
    • Bootstrap: P(Sharpe < 0) = 2.2%, 90% CI [0.69, 7.28] — statistically significant
    • Key insight: RKHS kernels aren't predictive of returns (architectural limitation),
      but vol-aware position sizing leverages what they implicitly detect (vol regimes)
  - Threshold sweep: entry_trend has no effect (MomentumGate range too narrow [0.489, 0.510]),
    choppy entry = 1.50 is optimal (selective in choppy regime). Exit_trending=0.10,
    exit_choppy=0.35 (quick exits) further improved from 1.43 to 1.56.
