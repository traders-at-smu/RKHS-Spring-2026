1. ADAPTIVE KALMAN Q BASED ON KERNEL AGREEMENT DISPERSION
═══════════════════════════════════════════════════════════════════════

Gemini's idea:  Q_t = Q_base × f(1 / σ²_kernels)
                When kernels agree → increase Q → filter updates faster → conviction
                When kernels disagree → decrease Q → filter stays conservative

Verdict: [TESTED] — Run 17: Sharpe 1.27 (vs Run 13's 1.55 with fixed aggressive Q)

Implementation (completed):
  - File: run_backtest.py (ADAPTIVE_Q env var) + backtesting/signal_definition.py
  - KalmanSignalGenerator now accepts Q_array (per-bar Q values)
  - 2-regime discrete: Q_high = pred_var (aggressive), Q_low = 0.1 * pred_var (auto)
  - Threshold: median of kernel prediction variance (σ² across 6 kernel outputs)
  - 50/50 split between high-conviction and low-conviction bars

Why it underperformed:
  - ElasticNet gives only 1 kernel (Macro) a non-zero weight (-0.024)
  - The other 5 kernels have zero weight → their predictions are pure noise
  - Measuring "agreement dispersion" across 5 noise channels + 1 real channel
    produces a meaningless variance metric
  - The adaptive Q is essentially flipping randomly between aggressive and
    conservative because there's no real multi-kernel agreement to detect

Why it will work later:
  - Once Sentiment + real Greeks produce non-zero ElasticNet weights, we'll have
    3-4 kernels with genuine signal → variance becomes a real agreement measure
  - The architecture is correct; it just needs more kernel diversity

Risk (Gemini flagged this correctly):
  - "Consensus traps" — all kernels wrong together during structural breaks
  - Mitigation: cap Q_max, and maybe add a "staleness" check — if all kernels
    have been agreeing for too long without a profitable trade, decay Q back down

When: Re-test after Sentiment + Greeks kernels arrive (8 sensors > 6).

2. DIFFERENTIABLE SHARPE LOSS IN THE COMBINER
═══════════════════════════════════════════════════════════════════════

Gemini's idea:  Replace MSE loss in ElasticNet with differentiable Sharpe ratio.
                Warm-start from MSE weights, fine-tune with Adam on Sharpe loss.

Verdict: [PARTIAL]

Why I partially agree:
  - The diagnosis is correct: MSE forces the combiner to chase outlier magnitudes
    it can never predict, wasting model capacity on the 1% of bars that drive 62%
    of SSE. A Sharpe-based objective would ignore magnitude and focus on sign.
  - The warm-start idea is clever — use ElasticNet solution as initialization.

Why I'm cautious:
  - We only have ~30 trades per walk-forward fold. Sharpe on 30 observations is
    extremely noisy. Gradient-based optimization on a noisy, non-convex loss with
    30 data points is likely to overfit catastrophically.
  - ElasticNet's L1/L2 regularization is doing important work (sparsity + stability).
    A custom Sharpe loss would need its own regularization scheme.
  - Simpler alternative: keep MSE but use Huber loss or trimmed MSE (drop the top
    5% residuals). This addresses the outlier problem without the overfitting risk
    of a full Sharpe objective.

What to change:
  - OPTION A (recommended): Switch ElasticNet to HuberRegressor or implement
    trimmed-MSE that excludes the worst 5% of residuals per fold
    - File: run_backtest.py, Stage 2 combiner section
    - Simpler, convex, still regularized, directly addresses the outlier problem
  - OPTION B (aspirational): Implement differentiable Sharpe after we have more
    trades (need 50+ per fold minimum to get stable gradients)
    - Would require a new optimizer loop outside of sklearn

When: Option A can be done now. Option B after more data / more kernels.

3. MULTI-STATE KALMAN OBSERVER (2D STATE SPACE)
═══════════════════════════════════════════════════════════════════════

Gemini's idea:  Expand from 1D Kalman state to 2D:
                State 1 = Directional Lean (mean-reversion vs trend)
                State 2 = Toxicity/Volatility (VPIN/Greeks-driven)
                Use State 2 for position sizing, State 1 for direction.

Verdict: [PARTIAL]

Why I partially agree:
  - Conceptually elegant. Separating "which direction" from "how confident/toxic
    is the environment" is exactly what practitioners do mentally.
  - The VPIN and Greeks kernels are naturally toxicity indicators — routing them
    to a separate state variable makes architectural sense.

Why I'm cautious:
  - A 2D Kalman filter has more parameters: 2×2 F (state transition), 2×2 Q
    (process noise), 2×1 H (observation), plus we'd need to decide which kernels
    map to which state. With 30 trades this is very hard to validate.
  - Simpler alternative: keep 1D Kalman for direction, use a separate heuristic
    for position sizing (e.g., scale position by inverse VPIN or by kernel
    agreement — which overlaps with item #1 above).

What to change:
  - SHORT TERM: Don't expand Kalman state dimension yet. Instead, use kernel
    agreement dispersion (item #1) as a position sizing multiplier alongside
    the 1D Kalman signal. This gets 80% of the benefit without the complexity.
  - LONG TERM: Once we have real Greeks (VannaCharm, GammaExposure), revisit
    2D state with a proper toxicity channel.

When: Long-term, after Greeks arrive and adaptive Q is validated.

7. REPLACE MSE WITH ROBUST LOSS (TRIMMED / HUBER)
═══════════════════════════════════════════════════════════════════════

Verdict: [TESTED] — Run 16: Sharpe -0.44 (Huber zeroed ALL kernel weights)

Implementation (completed):
  - File: run_backtest.py (COMBINER_LOSS=huber env var)
  - HuberRegressor with epsilon=1.35, alpha=0.001, StandardScaler
  - Switches from MSE to Huber loss in Stage 2 combiner

Why it failed:
  - Huber is "too honest" — it correctly identifies that NO kernel has meaningful
    correlation with returns (all per-kernel OOS correlations are -0.03 to +0.01)
  - Huber zeroed all weights to 1e-12 scale → predictions had variance 3.77e-16
  - Kalman filter had nothing to work with → strategy collapsed

Critical insight:
  - The profitable trading in Runs 11-15 DEPENDS on MSE being sensitive to outliers
  - MSE is slightly "fooled" by fat-tailed bars into keeping small non-zero weights
  - Those small weights → enough prediction variance → Kalman can extract regime
  - Huber removes the outlier sensitivity → removes the mechanism that generates signal
  - This is actually strong evidence for the "state observer" hypothesis: the strategy
    doesn't profit from return prediction, it profits from the Kalman filter detecting
    regime patterns in near-zero, noise-driven predictions

Why it may work later:
  - If Sentiment + Greeks kernels actually predict returns (even weakly), Huber
    will correctly preserve those signal weights while ignoring outlier magnitudes
  - The problem isn't Huber per se, it's that we have zero genuine predictive signal
    in the current 6 kernels — Huber just exposes this honestly

Alternative still worth trying:
  - Trimmed MSE (drop top 5% residuals) — less aggressive than Huber
  - May preserve enough outlier sensitivity to keep small non-zero weights
  - Or: Huber with very large epsilon (3.0+) to behave more like MSE for most bars

THINGS I DISAGREE WITH OR WOULD MODIFY FROM GEMINI (updated post Runs 18-19)
═══════════════════════════════════════════════════════════════════════

  1. "Move away from R² entirely" — Agree we shouldn't optimize for R², but we
     should still TRACK it as a diagnostic. If R² ever flips positive after adding
     Sentiment/Greeks, that tells us something important about those kernels.

  2. "Differentiable Sharpe with Adam" — Too aggressive for our data size.
     30 trades per fold is not enough for gradient-based optimization of a
     non-convex objective. Huber loss gets us 80% of the way there safely.
     UPDATE: Huber was also too aggressive — it zeroed everything. The MSE
     "sensitivity to outliers" is actually a feature, not a bug, in our case.
     It's what keeps kernel weights non-zero. We may need a GENTLER robust
     loss (trimmed MSE or Huber with high epsilon) rather than full Huber.

  3. "Multi-state observer now" — Premature. We need real Greeks first, and
     the adaptive Q gives us most of the benefit with much less complexity.
     The 2D state is a good idea for v2 of the pipeline.

  4. Gemini's framing of our system as a "state observer" — 100% agree.
     This is the best mental model for what's happening. The kernels measure
     microstructure state, the Kalman filter extracts a latent regime, and
     the trading signal comes from regime transitions, not return predictions.
     Run 16 (Huber) strongly confirms this: when you remove outlier sensitivity,
     you kill the mechanism that generates the non-zero predictions the Kalman
     filter needs. The strategy is a regime detector, not a return predictor.
     UPDATE (Runs 18-19): Fixed-weight tests further confirm — the Kalman
     profits from ElasticNet's walk-forward dynamics (time-varying intercept),
     not from any single kernel's static contribution. Even Macro at a fixed
     -0.024 is destructive (Sharpe -1.46). The edge is in the *process*, not
     the *weights*.

  5. "Adaptive Q based on kernel agreement" — Architecture is correct, but it
     needs multiple kernels with non-zero weights to work (Run 17). Currently
     only Macro has weight; the other 5 are zero → dispersion = noise.
     This will be the first thing to re-test when new kernels arrive.

  6. [NEW] "More kernels = better" — Not if they're from the same information
     source. Adding VannaCharm as a 7th kernel actually HURT by shifting
     ElasticNet's regularization path. The v2 architecture should have FEWER
     kernels (4) from MORE DIVERSE sources (order flow, news, options, macro)
     rather than 8+ kernels with correlated inputs.
